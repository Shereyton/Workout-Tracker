# Responsiveness and reliability audit

Release: 2.9.1. Implemented and verified locally before publication; user authorized the official release on October 12, 2026.

## Changes

- Build the Next up plan and Progress dashboard only when their tabs are visible.
- Cache dashboard inputs so clock-only updates do not rebuild unchanged cards, erase focus, or collapse expanded warm-ups.
- Reuse native exercise-plan source options until the available sessions change. Identify saved selections by workout identity rather than their position in a sorted list.
- Reuse saved-workout download rows while logging. Preserve the disclosure's open state when history changes.
- Use the shared history merger for saved-workout lists, including archived/exported sessions and completed workouts without duplicate copies.
- Cancel the previous rest timer's delayed hide when a new timer starts.
- Validate superset members before moving the active exercise into the session.
- Ignore a logging action if there is no active exercise; guard simultaneous exercise selection from shell controls.
- Add short touch feedback, explicit transition properties, 44px disclosure targets, and dock-aware scroll padding.
- Respect reduced-motion preferences for shell scrolling. Restore the dark-mode button to the header at desktop widths instead of behind the dock.

No storage migration, workout deletion, progression formula change, or export format change.

## Verification

- Full Jest suite: 16 suites, 208 tests passing.
- Added regressions for hidden-dashboard work, unchanged-plan node reuse, source-selection stability, rest-timer overlap, reduced-motion scrolling, and saved-row/disclosure reuse.
- Syntax checked script.js, calendar.js, app-shell.js, ai-export.js, progression-planner.js, and dev-server.js; diff whitespace check passed.
- Isolated Chrome browser checks at 320, 390, 430, and 1280px: real set logging, both exports, navigation, dark mode, reload persistence, no horizontal overflow, and no page errors.
- Synthetic 150-session history: logging-to-next-frame measured 41ms on this machine, with no hidden plan cards constructed. This is a local observation, not a performance guarantee for every phone.

WebKit runtime was unavailable. Physical iPhone/Safari testing remains a release-review step. Automated checks cannot prove the absence of every possible bug.
